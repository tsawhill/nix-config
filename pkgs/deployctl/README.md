# deployctl

`deployctl` is the deployment state machine for this Colmena fleet. Nix keeps
the machine-specific configuration and systemd schedules in
`modules/software/services/rebuild/default.nix`; Rust handles the operational
logic that was difficult to follow and test as one large shell script.

## Mental model

A scheduled host deployment has four explicit stages:

1. Build one host and discover its exact `nixos-system` store path.
2. Pin that closure locally and replace any older queued retry for the host.
3. Write a durable JSON retry record *before* attempting activation.
4. Copy and activate that exact path, deleting the record only on success or a
   non-network failure.

This ordering is intentional. If a host is offline, the retry timer activates
the already-built closure later instead of evaluating a newer flake. A newer
Daily, Weekly, or Monthly build for the same host supersedes retry state from
every older cadence.

All deploy modes share one `flock`. Scheduled jobs wait for it; interactive
deploys and retry passes skip when it is held. `build-nix` is ordered
penultimate and `server-nix` last because those machines host the controller
and its Incus container.

## Source map

- `cli.rs`: public commands and typed activation goals.
- `config.rs`: the JSON boundary generated by Nix (no secret values).
- `controller.rs`: manual, scheduled, retry, and rollback workflows.
- `colmena.rs`: builds, exact-path copies/activation, Wake-on-LAN, and GC roots.
- `hosts.rs`: Colmena selector expansion and safe deployment ordering.
- `retry.rs`: atomic JSON records and their Nix GC roots.
- `locking.rs`: the process-wide deployment lock.
- `notifications.rs`: Gotify and email summaries.
- `process.rs`: timestamped command execution and retained logs.

The compatibility commands remain available:

```text
deploy <host|@tag> [switch|boot|test]
deploy-old <host> <-N>
deploy-retry
```

`deployctl plan <selector>` resolves and prints ordering without building or
activating a host.

## Development

The package is built reproducibly through `pkgs/deployctl/default.nix` and its
committed `Cargo.lock`. Unit tests deliberately cover pure policy such as host
ordering, path discovery, and safe state labels. Keep subprocess and filesystem
effects behind their focused modules so more policy can become pure tests over
time.
